# 教程一：Omni 高端美食广告 Skill 安装与详细使用说明

更新日期：2026-09-07。本文对应本仓库的 `omni-food-ad-studio`，不是旧版 `food-ad-doubao-video`。

## 1. 先了解你会得到什么

输入菜名，或提供自己的实拍视频，Codex 按流程组织一支默认40秒的美食广告：四段各10秒，最终1080×1920竖屏、24fps，连续中文旁白，低音量环境声，不默认添加字幕或音乐。

“只给菜名”指启动时不用自己写分镜，不代表过程完全不用参与。你需要选择参考素材、逐段审片、确认口播稿、确认封面；登录、上传授权和额度不足时也需要处理。

本教程以 macOS 本地 Codex 环境为主要验证场景。其他系统需调整路径与浏览器控制方式，不宣称已验证所有系统。

## 2. 安装前的清单

| 项目 | 用途 | 何时需要 |
|---|---|---|
| Codex及本地文件访问 | 读取Skill、编排步骤、运行本地工具 | 全程 |
| Python 3.10及以上 | 建项目、剪辑、合成、验收 | 本地处理 |
| Node.js 20及以上 | 调用连续豆包TTS | 配音 |
| FFmpeg、ffprobe | 视频处理、音频混合和技术检查 | 本地处理 |
| Agent Reach | 渠道体检、菜谱与视频研究 | 需要网络研究时 |
| Flow账户及可用额度 | 联合参考生成广告镜头 | AI视频生成 |
| 已授权浏览器控制入口 | 在Flow选模型、添加附件、提交及下载 | 自动操作网页时 |
| 豆包TTS配置 | 生成连续旁白 | 配音 |
| MeTube或B站下载器 | 下载用户已选且许可范围明确的参考 | 对应平台下载时 |

ChatCut是可选入口，不是硬依赖。插件未连接时，使用随Skill附带的FFmpeg处理流程。MeTube需要其运行环境；已经运行的服务不要重复安装或暴露到公网。

可先对Codex说：

> 请检查这台电脑是否具备 omni-food-ad-studio 的依赖。先报告已有工具与缺项，不重复安装，不显示密钥，不发起收费生成。

已安装Homebrew的macOS，可按需安装缺失项：

```bash
brew install ffmpeg node python
python3 --version
node --version
ffmpeg -version
ffprobe -version
```

这些命令仅检查或安装基础工具，不安装Flow账户，不提供豆包额度。

## 3. 安装完整Skill目录

公开仓库：[pcyone/omni-food-ad-studio](https://github.com/pcyone/omni-food-ad-studio)。Git用户可先克隆到一个尚不存在的独立下载目录，再让Codex检查并安装完整目录：

```bash
git clone https://github.com/pcyone/omni-food-ad-studio.git omni-food-ad-studio
```

不要直接克隆覆盖已有安装；旧版本需先备份比较。

### 普通用户：下载后让Codex安装

在本仓库页面选择 Code → Download ZIP，解压后找到同时包含 `SKILL.md`、`scripts`、`references`、`agents` 的目录。不要只下载一个Markdown文件。

对Codex说：

> 请检查并安装这个本地 omni-food-ad-studio Skill 文件夹。安装到我当前Codex的skills目录；如果同名Skill存在，先备份并比较，保留我的自定义配置，不覆盖其他Skill。

默认安装位置为 `~/.codex/skills/omni-food-ad-studio/`；自定义 `CODEX_HOME` 时使用其 `skills` 子目录。GitHub下载的文件夹可能带 `-main` 后缀，安装后的目录名应为 `omni-food-ad-studio`。

安装后的结构至少包括：

```text
omni-food-ad-studio/
  SKILL.md
  agents/openai.yaml
  scripts/pipeline.py
  scripts/doubao.mjs
  references/
  examples/
  tests/
  docs/
```

### 确认安装成功

新开任务或刷新Skill列表，输入：

> 使用 $omni-food-ad-studio，先读规则并告诉我人工确认关口有哪些，暂不生成视频。

预期回答应包含选片、逐段视频、口播稿、封面四类确认。旧版 `food-ad-doubao-video` 可以共存，但本教程请明确调用新Skill名称。

如Codex未发现Skill，检查是否多套了一层目录、文件名是否为 `SKILL.md`，以及是否装在当前账户的实际skills目录。

## 4. 准备网络研究与下载渠道

安装Agent Reach前让Codex阅读其安装说明并检查已有版本，不盲目运行远程脚本。安装后的第一步是：

```bash
agent-reach doctor --json
```

doctor只表示渠道当前可用状态，不表示已经搜索、下载或取得授权。具体搜索命令应以已安装Agent Reach Skill为准。

相关上游入口：

- [Agent Reach安装说明](https://github.com/Panniantong/agent-reach/blob/main/docs/install.md)
- [MeTube项目](https://github.com/alexta69/metube)
- [B站下载器项目](https://github.com/qingsheng-git/bili-dl-cli)

YouTube参考可使用现有MeTube服务；B站参考可提供链接或BV号。先列候选、再由你选择，不能因为视频公开可看就直接拿去上传AI或商业改编。

如果你已有实拍素材，直接给文件即可跳过候选下载。请区分“允许本地剪辑”和“允许上传Flow”；它们不是同一项授权。

## 5. 准备Flow与豆包

### Flow

打开 [Flow](https://flow.google.com/)，由你完成登录。Codex应复用已授权页面，不读取或导出Cookie。模型、地区资格、费用与下载尺寸以你的当前页面为准。

本流程要求每次实际添加一段参考视频和五张参考图。只在素材库看见文件，不等于附件已经加到本次提示词。若当前模型或账户不支持联合输入，暂停并说明，不静默切换模型或丢掉附件。

没有可用浏览器控制通道时，Codex先交付四组提示词和素材，由你手动上传、生成、下载；每段仍须你确认后才继续下一段。

### 豆包TTS

使用你已开通服务的合法音色与配置。将真实密钥保存在仓库外的私密 `.env` 文件，并只告诉Codex路径，不把密钥粘贴到推文、截图或公开仓库。

配置格式如下，示例值不能实际调用：

```dotenv
DOUBAO_TTS_API_KEY=YOUR_PRIVATE_KEY
DOUBAO_TTS_RESOURCE_ID=YOUR_RESOURCE_ID
DOUBAO_TTS_SPEAKER=YOUR_LICENSED_SPEAKER
```

可选配置包括 `DOUBAO_TTS_MODEL`、`DOUBAO_TTS_SPEECH_RATE`。具体取值使用你服务后台的真实配置，不照抄别人的音色或资源ID。Skill支持通过 `--env` 或 `DOUBAO_TTS_ENV_FILE` 指定配置文件；已存在的环境变量优先。

## 6. 开始制作：两种输入

只有菜名时：

> 使用 $omni-food-ad-studio，菜名：客家碌鹅，制作40秒竖屏广告。先列参考视频让我选择；每段视频、口播稿、封面都按规则等我确认。

有自己的视频时：

> 使用 $omni-food-ad-studio，菜名：客家碌鹅。参考文件是我提供的实拍视频，我允许本地剪辑和取图，并允许将这些参考上传Flow。按40秒、四段各10秒制作，每段生成后先让我确认。

只想本地预处理时：

> 先只处理这份视频，做四段参考和20张图，暂不上传、暂不生成。

授权请按你的实际权利填写。源视频中若包含他人音乐、人像或商标，需要另行核查。

## 7. 逐步使用：每一步你要看什么

### 第一步：资料与选片

Codex整理菜谱做法、比例、地域差异、工序与来源。候选表应有标题、作者、链接、时长、完整度和已知许可范围。你选择具体候选后，才开始下载。换源时重新选，不混用旧参考。

### 第二步：40秒参考与20张图

先理解实际工序，再删重复内容、适当加速必要动作，组织四个语义段落。长教程不是机械平均切四份。只有你明确提供已剪好的40秒片并要求按10秒分段时，才按该切点处理。

每段选五个清楚、不同的动作状态，共20图。你应检查原料形状、熟度、工具、工序先后，以及图片是否模糊或遮挡。当前附带prepare脚本默认参考输出720×1280/24fps，最终成片才统一1080×1920；用户专项要求的1080p预处理属于单独适配。

### 第三步：四组提示词

每组写明对应10秒参考视频、五图的作用、分秒动作、相同厨具和光线、食物熟度及结尾状态。参考用于真实工序与视觉约束，不复制原作者的人脸、商标、字幕布局或旁白。

### 第四步：逐段生成、逐段确认

生成第1段，完成下载和检查后，Codex给你视频。你可以回复“第1段确认无误，继续第2段”，或指出问题。未确认前不会提交下一段，也不提前排队。第2、3段重复；第4段同样确认后才进入口播阶段。

已确认镜头若被重做或替换，新文件必须重新确认。自动技术检查通过不等于你已经同意。

### 第五步：口播稿人工定稿

根据四段实际画面写完整中文稿。你逐字检查菜名、动作、味觉描述、广告主张和语气。仅发送“修改如下”会作为新稿等待确认；可明确说“此版确认无误，开始配音和合成”。

定稿后不自行改词。如果测时不合适，需要改稿也先请你确认，不裁掉末字来凑40秒。

### 第六步：连续旁白与合成

一份稿件发起一次豆包TTS请求，不分成四次。测量真实时长后轻微变速，保留开头约0.2秒和结尾至少0.8秒。画面四段顺序不变；原声只有经过检查且适合使用时才压低混入，异常对白或音乐不能直接保留。

### 第七步：看片、听音、看验收

检查转场、手部、食物形状、最后一句与黑尾。技术报告不等于真人听过声音；文字稿确认也不等于音频发音正确。遇到听审未完成，报告保留待确认。

### 第八步：确认封面并保存

Codex从成品镜头导出封面，展示后等你回复“封面可以用”。确认后直接嵌入MP4，另存带封面版本，不重复询问是否保存。不会在视频开头加静帧，也不会修改原40秒配音。

改封面后重新确认。某些平台不读取MP4内嵌封面，发布时仍需单独选择提供的封面图。

## 8. 最终交付清单

- `outputs/菜名_40秒_带封面.mp4`：封面确认后保存的交付版。
- `outputs/final.mp4`：保留原成片。
- `outputs/封面.jpg`：独立封面。
- `outputs/关键帧检查.jpg`、`outputs/verification.json`：画面抽查与技术结果。
- `outputs/cover-verification.json`：封面嵌入后独立验收，不冒用原文件哈希。
- `narration.txt`、`approval.json`：最终文稿及人工确认记录。
- 参考清单、来源与权利记录：便于复查，不应不加筛选公开。

`technical_pass`表示技术指标；`creative_pass`需要画面、封面、声音审核；`commercial_ready`还依赖来源和权利证据。三个字段不能混用。

## 9. 故障与续跑

| 情况 | 正确处理 |
|---|---|
| Flow显示完成但下载失败 | 恢复同一任务下载，先查本地文件，不立即重新计费生成 |
| 视频有动作错误 | 指出当前段问题，只处理该段，重做后重新确认 |
| 只有720p | 保留原件并披露升采样，不标原生1080p |
| 旁白过长或过短 | 超出轻微变速范围则改稿并重新确认 |
| 上传因许可被拒 | 停止，换明确获准的素材，不尝试绕过验证 |
| 换了第四段 | 新段重新审片，更新文件哈希，不能沿用旧生成证据 |
| 封面不显示 | 查看是否被播放器忽略，发布时选择独立图片，不擅自改片头 |
| 想继续未完成项目 | 提供原项目路径，让Codex读取确认状态，从未完成步骤续跑 |

## 10. 更新、检查与隐私

更新先备份同名Skill，再比较和安装。教程及规则是代理行为约束；当前脚本不会自动生成全部审批记录，也不会自主完成网页操作，不应脱离Codex直接批量执行绕过确认。

在Skill目录可运行以下无收费检查：

```bash
python3 -m unittest discover -s tests -v
node --check scripts/doubao.mjs
```

不要提交 `.env`、Cookie、认证目录、私人项目媒体、旁白音频或包含密钥的日志。本仓库公开不等于任何第三方素材或音色自动取得商用许可。
