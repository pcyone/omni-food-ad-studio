# 参考剪辑、混音与验收

## EDL 格式

`pipeline.py init` 创建占位 EDL。观察完整教程后，把 `source` 改为已下载文件的绝对路径，每段 ranges 指明源起止及输出时长。例：源20–28秒压至4秒=`speed=2`。一段可有多范围，`output_seconds` 合计必须10。默认0.5–6倍速度，仅删冗余并适度加速必要动作；不保留无意义铺垫来凑40秒。排序须保持源时间前进；如源片把成品放在开头，先找到真正结尾成品，或另行记录获准的叙事重排再改脚本，不伪造时间线。

每段 `frames` 是5个对象：`second`（剪后0–10之间）、`label`（实际动作）。脚本拒绝缺标签、重复时间、越界或非10秒段。横屏教程参考以适配留边保留操作区域，不粗暴裁掉锅和手；参考不承担最终竖屏画质。音轨默认移除，免把原作者讲解传给模型。

```json
{"source":"/绝对路径/source.mp4","scenes":[{"id":"01","label":"备料腌制","ranges":[{"start":20,"end":28,"output_seconds":4},{"start":31,"end":40,"output_seconds":6}],"frames":[{"second":0.5,"label":"主料"},{"second":2,"label":"切料"},{"second":4.5,"label":"入调料"},{"second":7,"label":"抓匀"},{"second":9,"label":"腌好"}]}]}
```

实际需要01–04四个场景。运行 prepare 得40秒参考、4个10秒MP4、20张JPEG、20帧联络表、来源hash及时间映射。剪后必须检查动作，不把脚本成功当创意通过。

## 连续旁白及终端验收

- 配音前先核对四段当前视频均已获用户人工确认，再展示完整口播稿并暂停等待定稿确认；将稿件路径、SHA256及用户确认依据写入 `approval.json`。未确认不得调用TTS、复用旧声音或开始最终合成。改稿（包括时长适配）后重新确认，不能将用户仅提交修改稿视为定稿授权。用户明确确认后按原文制作，不自行修改。
- 合成前再次核对当前视频与已确认稿件的哈希；替换片段或改稿后，必须取得对应新版本确认。文字稿确认不等于合成音频听审，两者分开记录。

- 最终视觉只接受四段已验收10秒9:16素材，不裁、倒序、拉伸或静帧补时。统一24fps；若输入30fps会按时间重采样，不改变时长。源横屏不自动裁切，回生成阶段纠正。
- 一次TTS→完整原声→测时→`tempo = raw_duration / 39`，范围0.88–1.18。保留0.2秒起始、至少0.8秒末尾，变速后再次测量，不能只凭公式推断。
- 人声响度目标-16 LUFS，峰值-1.5dBTP；背景起始增益0.12，再由实听调整。整体二次响度归一，避免混音削波。无语音淡出、不反向裁尾。默认无额外BGM。
- 输出有声但“旁白是否完整/音色是否好听”仍需听、或合法可用转写工具辅助；音量检测不能替代听审。最后6秒单独导出供听审。
- 自动验收：40秒±一帧、1080×1920、24fps、H.264/yuv420p、AAC48k双声道、全片解码、≥0.5s黑场、整体LUFS/真峰、独立人声音轨末尾≥0.8s保护、960视频帧。
- 关键帧包括普通镜头及9.958/10/19.958/20/29.958/30秒转场两侧和39.5秒；人工确认不穿帮、不黑尾、没有未经计划的突切。
- 自动结果生成 `verification.json`；人工审核写 `review.json` 中独立字段，附当前最终视频sha256，重渲染则旧审核失效。
- `commercial_ready` 只有技术通过、当前哈希对应的视觉/口播审核通过、完整生成证据和所有权利证据确认时才为true。它代表流程审核记录，不是法律保证。

## 封面人工确认与嵌入

封面默认选38秒，代理先检查它是否为完整成品英雄镜头，必要时用 `--hero-second` 改到30–39.9秒。随后必须展示实际 `封面.jpg`，等待用户明确确认可用；代理目视通过不能替代用户确认。用户确认后直接嵌入并另存带封面MP4，不再重复询问是否保存。封面路径、SHA256、确认原话和时间记录于 `approval.json`；改图后重新确认。

默认用MP4附加图片封面，不在开头插入静帧、不改首帧、不延长或裁切原40秒，不重新编码画面和配音。保留 `final.mp4` 与独立 `封面.jpg`；新文件名使用 `菜名_40秒_带封面.mp4`，已存在则递增版本，不覆盖旧版。代理核对确认记录后可按以下已验证方式执行（替换为真实绝对路径）：

```bash
ffmpeg -n -v error -i /绝对路径/outputs/final.mp4 -i /绝对路径/outputs/封面.jpg -map 0:v:0 -map 0:a:0 -map 1:v:0 -c copy -disposition:v:1 attached_pic -movflags +faststart /绝对路径/outputs/菜名_40秒_带封面.mp4
```

用ffprobe验证主视频仍40秒、1080×1920、24fps，封面流 `attached_pic=1`；提取封面核对与已确认图片一致。分别对源文件与新文件主视频/音频执行 `-map 0:v:0 -map 0:a:0 -c copy -f streamhash -hash sha256 -`，确认两路哈希不变。保存 `cover-verification.json`，包含源成片、确认封面和新MP4的文件哈希、实际检查结果及原验收报告路径。新容器哈希会变化，不覆盖或冒用绑定原成片哈希的 `verification.json`；封面确认也不代表口播听审或商用授权通过。

交付时优先链接带封面MP4，同时保留独立封面。部分播放器/发布平台会忽略内嵌封面，须如实提示发布时可能还要单独选择封面，不承诺所有平台自动显示；不因此擅自改成片头静帧或上传发布。
