# 研究、来源与商业用途检查

先 doctor，再用 Agent Reach 已安装 Skill 中实际存在的命令。网络沙箱报 DNS 错误可按产品权限申请正常联网重试；不能把 DNS 错误等同于工具未安装。研究输出到项目 `research.md`，记录访问日期、渠道实际结果（包括失败）。不要声称“全网所有平台均检索完”。

已在本机检查的查询形式：

```bash
agent-reach doctor --json
mcporter call exa.web_search_exa query="子姜炒牛肉 做法 配比" numResults=5
bili search "子姜炒牛肉" --type video -n 5
bili video BV1NM4m1U7AW
bili-dl dl BV1NM4m1U7AW --output /绝对路径/项目/source
agent-reach check-update
```

以上BV是研究候选，不是已获商业授权的素材。下载器帮助可能更新，使用前 `--help`；YouTube 搜索/元数据按 Agent Reach 视频指南，实际下载按 MeTube。不要自行抓取 Cookie 文件。安装器或下载器提示读取浏览器登录态时遵守宿主权限；凭据不进入项目。

## 下载前选片关口

先展示候选表，再等待用户选择。每项包含编号、标题、来源链接/BV号、作者、时长、工序完整度、画面清晰度/可取帧情况和授权状态。未核实时写“待核实”，许可未知写“未查到明确许可”，不把推荐写成已选。此阶段只查元数据及可合法查看的页面，不预先下载候选视频。

用户选定后，记录项目 `source-selection.json`：候选链接、selected_source、用户选择原文/日期、允许本地下载剪辑的范围、允许外部AI上传的范围及各自证据。用户选择与许可确认可以合并一次询问，但“选这个”本身不是对所有权利的声明。确认后仅处理所选来源；若需换视频，重新征求选择。

用户提供实拍文件时记录绝对路径、哈希与用户来源声明，跳过候选和下载。局部请求只执行该局部工作；外部上传遵循已获明确授权，不因文件可读而扩大范围。上传成功是技术结果，不应据此回填商业权利为confirmed。更换素材后旧来源记录和旧文件保留，新来源另行记录，不能继承旧文件的生成/授权证据。

## 资料表与视频比较

每个菜谱记录 URL、作者、标题、访问日期、原始数量和单位、工序摘要、可信依据。优先原作者/厨师的一手教程；至少两来源交叉核实动作顺序。主辅料有明确克数才能算重量比；“一勺”不可未经测量擅自写成15克，“适量”保留适量。没有统一标准时说明选择了哪一地域/作者版本。不得从相互矛盾配方拼出声称原作者认可的新配方。

视频至少比较：完整性（备料/处理/烹饪/成品）、动作清晰度、镜头遮挡、可提取帧质量、和选定配方的一致性、许可情况。优先推荐许可明确的自有、明确允许改编及外部处理的素材，但由用户最终选择；只有普通公开教程时可研究工序，不能自动认定准许上传Flow或出现在广告中。下载成功须保存来源URL、作者、文件hash、ffprobe、完整解码结果；若未观看，不写已核实完整。

## rights.json

init 会创建待核验表。每项要有 `status: confirmed` 和非空 `evidence`（授权邮件、合同、来源许可页及保存日期，或用户明确拥有素材权利的确认）。这些字段是审核声明，不是法律引擎。至少覆盖：

- reference_local_use：本地获取、剪辑研究的依据。
- reference_ai_upload：向外部AI平台上传、处理参考视频及抽帧的依据。
- reference_commercial：第三方内容被广告改编/使用的许可范围；如未使用其表达而只学公共烹饪事实，须记录独立制作依据及审核判断。
- model_terms：实际账户/服务当前适用条款及商业使用条件。
- voice：音色/克隆授权及豆包服务用途；不能仅凭能调用API就视为可商用。
- likeness_brand：人像、商标、包装、场景的授权或经复核不含此类对象。
- music_sound：环境声和音乐的来源；默认无外加音乐，仍检查生成音轨是否含受保护音乐/不明对白。

缺上传许可时停在上传前；缺最终用途证据时交付“待商业审核”技术样片。不能靠删除水印解决许可。商业发布若涉及地区性广告或食品安全声明，应另作专业审查；本 Skill 不提供法律保证。
